# ESKD_Specia_SchlosserV — спецификация по ГОСТ 2.106 и групповая по ГОСТ 2.113-75, вариант Б

Прежнее имя надстройки — GroupSpecB. Внутренние имена (атрибут чертежа `GroupSpecB/Data`, папка
`%APPDATA%\GroupSpecB` с параметрами и журналом, ClassId) не менялись: сохранённые спецификации и
параметры продолжают работать. `build.ps1 -Install` удаляет прежний `GroupSpecB.addin`.

Надстройка-компаньон к ESKD Specia для Autodesk Inventor 2026. Формирует групповую спецификацию,
в которой у каждого исполнения своя графа «Кол. на исполн.» (вариант Б, п. 5.5.2 ГОСТ 2.113-75):

* первый лист — **форма 1б** (без граф «Лит.»/«Код»), основная надпись по ГОСТ 2.104 форма 2;
* последующие листы — **форма 1а**, основная надпись форма 2а;
* А4 альбомный, поле подшивки сверху 20 мм, дополнительные графы ГОСТ 2.104 над рамкой,
  графы 6 / 6 / 8 / 70 / 63 / 10×10 / 34 мм, головка 15 мм, строки 8 мм.

ESKD Specia не трогается: надстройка работает сама по себе и хранит свои данные отдельно.

## Спецификация по ГОСТ 2.106 или групповая

Команда **«Спецификация»** выбирает тип по числу 3D-моделей (исполнений): **одна** — спецификация по
**ГОСТ 2.106**, **несколько** — групповая по ГОСТ 2.113 (вариант Б). Тип переключается вручную списком
**«Тип»** в начале панели редактора: «По числу 3D-моделей», «ГОСТ 2.106», «ГОСТ 2.113». Выбор хранится в
чертеже. Чертежи с групповой спецификацией, сформированной до появления ГОСТ 2.106, остаются групповыми.

Спецификация по ГОСТ 2.106 редактируется и формируется так же, как групповая (те же строки, разделы,
позиции, правки, запись в модели), отличаются только листы и графа количества:

* первый лист — **форма 1**, основная надпись форма 2; последующие — **форма 1а**, основная надпись форма 2а;
* А4 книжный, поле подшивки слева 20 мм, дополнительные графы ГОСТ 2.104 в поле подшивки
  («Инв. № подл.» … «Подп. и дата»; на первом листе — «Перв. примен.» и «Справ. №»);
* графы 6 / 6 / 8 / 70 / 63 / 10 / 22 мм, головка 15 мм, строки 8 мм; 29 строк на первом листе и 32 на
  последующих (параметры «ГОСТ 2.106: строк на …»), таблица доходит до основной надписи;
* одна графа **«Кол.»** — количество основного (первого включённого) исполнения; строки, которые есть только
  в других исполнениях, в спецификацию не входят и не нумеруются; у документов «Кол.» не заполняется;
* обозначения исполнений пишутся полностью (сокращение «-02» — правило только групповой);
* «Сборочный чертеж» — полное обозначение изделия + «СБ» (например, «…-06СБ»);
* листы называются «СП-N» (у групповой — «ГС-N»); при смене типа листы прежнего типа заменяются.

## Откуда берутся исполнения

Исполнения читаются из **BOM** (структурированный вид, первый уровень) моделей исполнений:

| Запуск команды | Исполнения |
|---|---|
| **Из чертежа** | все сборки, показанные в видах на **всех листах** чертежа (кроме листов самой спецификации). Каждая модель — отдельное исполнение. Номер исполнения определяется по её обозначению (Part Number): «АБВГ.543835.926» → «–», «…-02» → 02. Повторные виды одной модели учитываются один раз, виды деталей пропускаются |
| Из фабрики iAssembly | строки таблицы; обозначение — из столбца «Part Number» |
| Из сборки с состояниями модели | каждое состояние, кроме замещающих |
| Из обычной сборки | одно исполнение |
| Кнопка **«Добавить исполнение (3D-модель)…»** | ещё одна сборка (.iam) — ещё одна графа «Кол. на исполн.». Добавленные исполнения хранятся в данных спецификации и при повторном запуске сохраняются |

Графы исполнений идут по возрастанию номера, первое (основное) — «–». Чтобы прочитать фабрику
iAssembly или сборку с состояниями модели, надстройка по очереди делает активным каждое
исполнение, а затем возвращает исходную строку или состояние.
Для каждой составной части: обозначение — Part Number, наименование — Description или Title
(настройка), примечание — «Примечание». Графа **«Формат»** заполняется только в разделах
«Документация», «Сборочные единицы» и «Детали»: из пользовательского свойства **LastFormat** модели
(если его нет — из «Формат»).

При запуске из сборочного чертежа формат его первого листа (А0…А4, дополнительные вида А4х3)
пишется в графу «Формат» строки «Сборочный чертеж». По кнопке «Сформировать» он же записывается
в LastFormat специфицируемой сборки: в файл сборки исполнения, а для членов iAssembly — в фабрику.
Раздел определяется так:

1. пользовательское свойство **`spec_section`** модели (у членов iPart/iAssembly — фабрики), а
   также старые «Раздел спецификации» / «Раздел СП» / «Раздел», если значение совпадает с
   названием раздела;
2. иначе: Content Center (не custom) или **в наименовании/обозначении есть слово ГОСТ, ИСО, ISO, DIN** → «Стандартные изделия»; покупная (Purchased) → «Прочие
   изделия»; количество не в штуках → «Материалы»; сборка → «Сборочные единицы»; деталь → «Детали».

## Слияние строк и количества

* Элементы с одинаковым **обозначением**, а если обозначения нет — с одинаковым **наименованием**,
  сливаются в одну строку, количества по каждому исполнению суммируются. Например, одна деталь в
  виде нескольких файлов-копий даёт одну строку.
* Дробные количества (в первую очередь у «Материалов») округляются до 3 знаков после запятой, нули в
  конце не пишутся: 666,6666 → 666,667; 0,500 → 0,5.

## Изменения в 3D-моделях — только по кнопке «Сформировать спецификацию»

Пока открыт предпросмотр, модели не меняются. После нажатия «Сформировать спецификацию»:

1. Если обозначение или наименование исправили в предпросмотре, они переносятся в свойства
   моделей: Part Number и Description (или Title — по настройке «Наименование берётся из»). Для
   слитой строки правка пишется во все её файлы. После записи значения снова берутся из модели.
2. Записывается `spec_section` (см. ниже).
3. Перенумеровываются позиции в BOM сборок (см. «Номера позиций в сборке»).

Обозначение и наименование члена iPart/iAssembly задаются таблицей фабрики, поэтому надстройка их
не меняет и сообщает об этом в отчёте. То же для файлов-копий с одинаковым внутренним именем:
Inventor не может открыть их одновременно и вместо копии отдаёт уже загруженный оригинал.

## Параметр spec_section

По кнопке «Сформировать» раздел каждого элемента записывается в пользовательское свойство
`spec_section` его модели. Если элемент перенесли в другой раздел вручную, записывается новый раздел.
При следующем запуске раздел читается из `spec_section`. Модель сохраняется сразу, если в ней не
было несохранённых правок; иначе свойство только записывается, а сохранить модель нужно самому.
Члены iPart/iAssembly изменить нельзя, поэтому свойство пишется в их фабрику (оно общее для всех
членов фабрики). Отчёт о том, что записать не удалось, показывается после формирования.

## Основная надпись

Графы основной надписи на листах спецификации — **ссылки на свойства чертежа**: их значения
меняются вместе со свойствами, перерисовывать спецификацию не нужно.

| Графа | Свойство чертежа |
|---|---|
| Обозначение | «Обозначение» (Part Number) |
| Наименование | «Описание» (Description), вкладка «Проект» |
| Организация | «Компания» (Company) |
| Разраб. | «Проектировщик» (Designer), вкладка «Проект» |
| Пров. | «Проверил» (Checked By), вкладка «Статус» |
| Т.контр. | «Т. контр.» (Engineer) |
| Н.контр. | «Нормоконтроль» (Engr Approved By), вкладка «Статус» |
| Утв. | «Утвердил» (Mfg Approved By), вкладка «Статус» |
| Лит. (первая графа) | Litera, набор GOST Properties |

Вкладка **«Основная надпись»** показывает текущие значения граф: из 3D-модели специфицируемой
сборки (основное исполнение; для члена iAssembly — фабрика), если там пусто — из чертежа, если пусто
и там — значения по умолчанию. Цвет поля показывает, откуда взято значение. Здесь же задаются
дополнительные графы чертежа (Инв. № подл., Перв. примен., Справ. №).

Если исправить графу на этой вкладке, по кнопке «Сформировать» новое значение записывается **в
свойство 3D-модели и в свойство чертежа**. Модель сохраняется, если в ней не было несохранённых
правок. Неисправленные графы копируются в чертёж по правилу «модель → чертёж → по умолчанию».

Значения по умолчанию задаются на вкладке **«Параметры»** (группа «Основная надпись: значения по
умолчанию»). **Все параметры этой вкладки общие для всех чертежей**: они хранятся у пользователя в
`%APPDATA%\GroupSpecB\Settings.xml` и сохраняются сразу при изменении. Базовое обозначение
исполнений и дополнительные графы у каждого чертежа свои: первое задаётся на вкладке «Исполнения»,
вторые — на вкладке «Основная надпись».
**Родительский компонент.** Источник свойств основной надписи — 3D-модель основного (первого
включённого) исполнения групповой спецификации, а для члена iPart/iAssembly — его фабрика. Первый вид
чертежа может показывать другое исполнение («-02»), поэтому он используется, только если исполнений
ещё нет (листы спецификации не учитываются).

* **При каждом сохранении чертежа с групповой спецификацией** надстройка копирует свойства основной
  надписи (обозначение, наименование, организация, Разраб., Пров., Т.контр., Н.контр., Утв., литера) из
  родительского компонента в свойства чертежа. Пустые в модели значения не переносятся. Это заменяет
  ассоциирование свойств ESKD Specia — в Specia его нужно отключить. Чтобы так же обрабатывались **все**
  чертежи, включите параметр «Свойства при сохранении: все чертежи» (по умолчанию выключен).
* Графы, исправленные на вкладке «Основная надпись», по кнопке «Сформировать» записываются **в
  родительский компонент** (фабрика сохраняется) **и в чертёж**. Таблицу фабрики и члены iAssembly
  надстройка при этом не трогает.
* **Материал детали в чертеже** (как в ESKD Specia). В любом чертеже, где первый вид — деталь, в
  пользовательские свойства чертежа записывается её материал. Материал из трёх частей
  «Сортамент\Марка\Стандарт» (или через «|») раскладывается в `RollingMaterial`, `MaterialUpLine`,
  `MaterialDownLine`, а `MaterialLine` заполняется «_» на длину большей из двух строк + 1; остальные
  свойства пусты. Любой другой материал — в `SingleMaterial`. Если в `SingleMaterial` вручную записано
  «-», «_» или «см. …», он не перезаписывается, а дробь очищается. Без детали в первом виде свойства
  очищаются. Обновляется при открытии/активации чертежа, после вставки, замены и удаления вида, после окна
  iProperties, перед печатью и сохранением. Выключается параметром «Свойства материала в чертеже детали».
**Дата и подпись.** В строках «Разраб.», «Пров.», «Т.контр.», «Н.контр.», «Утв.», где есть фамилия:

* графа «Дата» — ссылка на свойство чертежа «Дата создания»; Inventor выводит её как дд.мм.гг;
* в графу «Подп.» поверх эскиза вставляется эскизное обозначение чертежа, имя которого совпадает с
  фамилией (или с её первым словом, если в свойстве есть инициалы). Точка вставки — левый нижний
  угол графы. Если такого обозначения нет, графа остаётся пустой.

На вкладке «Основная надпись» дату можно поменять: правая кнопка мыши на графе «Дата» открывает
календарь, по умолчанию выбрана сегодняшняя дата. Выбранная дата по кнопке «Сформировать»
записывается в «Дата создания» чертежа — одну на все строки.

Литеру Inventor хранит в ссылке как свойство модели (`Document='model'`, так её использует и
штамп ESKD). На листе без видов показывается значение литеры из чертежа.

Наименование, как в штампе «Надпись чертеж 1», — надпись в прямоугольнике графы 70×25 мм: Inventor сам переносит его по словам на нужное число строк. Шрифт подбирается при формировании по длине наименования: 5 мм — до 3 строк, 3,5 мм — до 4, иначе 2,5 мм. Длинное значение остальных граф сжимается по ширине. Если значение потом
изменится, сжатие пересчитается при следующем формировании.

## Номера позиций в сборке

При формировании спецификации (параметр «Перенумеровать позиции в сборке», включён по умолчанию)
номера позиций спецификации записываются в BOM родительских сборок исполнений: структурированный
вид, номер строки равен позиции, номер блокируется. Строки BOM, которых нет в спецификации,
получают следующие свободные номера. Выноски на чертежах берут номера из BOM.

* **Фабрика iAssembly** (запуск из фабрики или виды членов в чертеже): правится фабрика, она
  сохраняется, затем пересоздаются члены, которые входят в спецификацию.
* **Сборка с состояниями модели**: номера проставляются в каждом состоянии с областью правки
  «все состояния».
* **Отдельная сборка исполнения** правится и сохраняется.
* Если в сборке были несохранённые изменения, номера записываются, но сохранять её нужно самому.

Порядок записи в разделе строится по базовому обозначению (исполнения одной детали — подряд), а не
по номерам BOM, поэтому повторная перенумерация не меняет порядок.

## Переносы и сжатие текста

* Если в тексте графы (наименование, обозначение, примечание) есть **`$`**, это конец строки:
  текст после него пишется с новой строки. Строка, которая не помещается в ширину графы,
  **сжимается** (коэффициент сжатия надписи), а не переносится.
* Если `$` нет, текст переносится по словам по ширине графы. При формировании листов ширина
  надписей меряется шрифтом листа; в редакторе (число листов в строке состояния) — оценивается по
  параметру «Средняя ширина символа».
* Любая надпись, которая всё равно не помещается в графу, сжимается по ширине.

## Правила ГОСТ, которые выполняются автоматически

* Порядок разделов по ГОСТ 2.106; перед заголовком раздела и после него — пустая строка, заголовок
  подчёркнут и не остаётся последней строкой листа; запись не разрывается между листами.
* Составные части основного (первого) исполнения записываются первыми, не применявшиеся в нём —
  в конце раздела (п. 5.5.2 д).
* **Позиции.** У каждой составной части свой номер позиции, и он пишется в каждой её строке.
  Нумерация сквозная по всем разделам, «Документация» не нумеруется. **Каждый следующий раздел
  начинается с пропуском номеров** — резерв в конце предыдущего раздела (по умолчанию 2, параметр
  «Резерв номеров позиций в конце раздела»). Номер, введённый вручную,
  сохраняется, остальные строки получают следующие свободные номера. О повторах предупреждает
  строка состояния. Варианты одного места в изделии (один номер позиции в BOM) записываются
  подряд, но каждый со своим номером.
* **Сокращение обозначений** (п. 5.3): если подряд на листе идут части с одинаковым базовым
  обозначением, вторая и следующие пишутся как «-02», формат указывается только у первой.
  «-02» начинается со смещением от левого края на ширину базовой части обозначения — ровно под
  номером исполнения полного обозначения.
* В разделе «Документация» ставится «X» (п. 5.5.2 г). Строка «Сборочный чертеж» (<базовое>СБ)
  добавляется автоматически.
* Заголовок графы — «Кол. на исполн. <базовое обозначение>-», под ним номера исполнений («–», 01, 02…).
* **Больше 10 исполнений** (п. 5.5.2 е, ж): для каждого следующего десятка таблица повторяется на
  отдельных листах (только строки, применяемые в этом десятке). Левее основной надписи первого листа
  пишется «Исполнения 10 ... 19 — см. листы 4, 5».
* Количество пишется в первой строке записи (в одной строке с номером позиции); длинный текст переносится по ширине графы.

## Работа

1. Откройте сборочный чертёж с видами исполнений и на вкладке **Размещение видов** нажмите
   **Спецификация ГОСТ → Спецификация**. Листы спецификации «ГС-N» (по ГОСТ 2.106 — «СП-N») будут добавлены в этот же
   чертёж; они исключены из счёта листов чертежа и нумеруются отдельно. Можно запустить команду и
   из параметрической сборки (вкладка **Сборка**): тогда создаётся новый чертёж.
2. В редакторе:
   * **Обновить из BOM** — перечитать исполнения. Исправленные вручную ячейки (выделены жирным)
     не перезаписываются.
   * **Добавить исполнение (3D-модель)…** — выбрать сборку исполнения (.iam), её BOM станет
     новой графой. Удалить добавленное исполнение можно на вкладке «Исполнения».
   * **Добавить строку** — документ, материал, свободная запись.
   * Флажок **«В СП»** исключает строку BOM из спецификации (при обновлении она не вернётся).
   * **▲ / ▼**, **Сортировать по ГОСТ**, **Перенумеровать**.
   * Таблица показывает заголовки разделов и пустые строки после разделов, как на листе.
   * Вкладка **«Исполнения»** — включение исполнений и подписи граф.
   * Вкладка **«Параметры и основная надпись»** — обозначение, наименование, подписи, литера,
     организация, число строк на листах, шрифт.
3. **Сформировать спецификацию.** Листы «ГС-N» пересоздаются, остальные листы чертежа не трогаются. Сохраните чертёж: все данные
   редактора (ручные строки, правки, настройки) хранятся в нём, в атрибуте `GroupSpecB/Data`.

Листы рисуются эскизом «Групповая спецификация» на каждом листе. Текстовые стили `ГС_*` создаются
в чертеже (по умолчанию шрифт GOST Common, наклонный, 3,5 мм).

## Сборка и установка

Visual Studio не нужна: используется компилятор .NET Framework 4.8 из Windows.

```
powershell -ExecutionPolicy Bypass -File build.ps1 -Install
```

Скрипт собирает `bin\ESKD_Specia_SchlosserV.dll`, `bin\TestRunner.exe`, `bin\UnitTests.exe` и копирует
`ESKD_Specia_SchlosserV.addin` с полным путём к собранной DLL в `%APPDATA%\Autodesk\Inventor 2026\Addins`. В исходном
`ESKD_Specia_SchlosserV.addin` путь относительный — его подставляет скрипт, так что папка может лежать где угодно. После этого перезапустите Inventor. Для другой версии
используйте `-InventorVersion 2025` (interop-типы встроены в DLL; проверено только на Inventor 2026).

`build.ps1 -Test` дополнительно запускает `UnitTests.exe` — проверки логики без Inventor (сведение BOM,
разделы, позиции, номера исполнений, сокращения «-02», вёрстка листов и десятков). Их же можно
собрать и запустить на любом компьютере с .NET Framework или Mono.

`TestRunner.exe <сборка.iam | чертёж.idw> <выход.idw> [--form] [--add исполнение.iam] [--type 2.106|2.113]` подключается
к запущенному Inventor и проверяет всю цепочку без загрузки надстройки: собирает исполнения,
формирует листы, сохраняет .idw и .pdf. Загруженную в Inventor DLL перезаписать нельзя, поэтому
для тестов собирайте в другую папку: `build.ps1 -OutDir bin_dev`.

## Журнал ошибок

Ошибки, которые надстройка не показывает в окне (например, при сохранении чертежа или при прерывании
транзакции ESKD Specia), пишутся в `%APPDATA%\GroupSpecB\GroupSpecB.log`. Если что-то работает не так,
приложите этот файл к описанию проблемы.

## Особенности Inventor API (учтены в коде)

* Пока в .NET живы обёртки над `BOMView`/`BOMRow`, Inventor **не пересчитывает BOM** после смены
  строки iAssembly или состояния модели: количества остаются от первого прочитанного исполнения.
  Поэтому перед каждым переключением вызывается `GC.Collect()` (`ReleaseBomReferences`).
* Числа в разметке `<StyleOverride FontSize='…'>` Inventor читает в формате локали (в русской —
  с запятой). Поэтому размеры текста задаются отдельными текстовыми стилями, а не разметкой.
* Файлы старых версий (например, примеры MechaniCS 2016 года) нужно мигрировать (открыть и
  сохранить), иначе `BOMRows` возвращает E_FAIL.
